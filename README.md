# LubanEditor · Luban配表助手

Luban配套编辑工具，让任何人使用Luban更简单！

**工具主要解决的问题：**

1. 将Luban复杂的语法、规则及配表方式可视化和简化，几乎零门槛入门；
2. 无需关注Schema文件的编写与维护，由工具自动完成；
3. 任何人都可以创建和维护表；

[Luban官方文档](https://www.datable.cn/docs/intro)

---

## 1. 两种用法

### A. 直接跑源码（你需要 Python）

```bat
run.bat          :: 自动建 .venv、装依赖、启动
```
或手工：
```bat
python -m pip install -r requirements.txt
python main.py
```

### B. 打成 exe，发给别人直接用（对方不需要 Python）

```bat
build.bat
```
会依次完成：找 Python → 建 `.venv` → 装依赖 → 生成示例工程 → PyInstaller 打包 → **自动自检** → LubanEditor.exe`（约 37MB，双击即用；想要启动更快的单目录版，
先 `set LUBANKIT_ONEDIR=1` 再跑 build.bat）。图标由 `make_icon.py` 生成（`app.ico`，打包时自动带上，没有也不影响）。

只想在本机快速重打一包（已有装好 PySide6 / openpyxl / pyinstaller 的环境时）：

```bat
python -m PyInstaller LubanEditor.spec --noconfirm --clean
```

- 产物：`LubanEditor.exe`，单文件，**56~90MB**，`--noconsole` 不弹黑框
- 只有构建这一次需要 Python；构建出来的 exe 双击即用、不联网、不依赖python环境
- 对方首次启动会解压到临时目录，慢 5~15 秒属正常
- 想更快：`set LUBANKIT_ONEDIR=1 && build.bat` 出单目录版（整个文件夹一起拷）

> 打包配置 `LubanEditor.spec` 已经过验证：砍掉 QtWebEngine / Qt3D / QtQuick / QtQml /
> QtMultimedia 等用不到的子模块（PySide6 全量能到 1GB+，砍完约 1/10），
> 并在打包后跑 `--selftest` 确认 Qt / openpyxl / 界面 / 工程导入都正常。


## 2. 它到底做了什么

| 能力 | 说明 |
|---|---|
| 工程探测 | 从 `luban.conf` 读 `schemaFiles / dataDir / groups / targets`，自动定位三张定义文件；**目录没有任何要求**，随便选一个文件夹都能打开 |
| 通用列名 | 列名不硬编码，用**语义别名表**匹配。你工程里写 `define_from_file` 还是 `read_schema_from_file`、`valueType` 还是 `value_type`，都能认 |
| 新建 / 删除 / 修改表 | mode、index、group、input、read_schema_from_file 全在表单里；删除表时**声明与数据文件分开处理**：「只删声明（保留数据文件）」或「连数据文件一起删」，不会误删 |
| 字段编辑 | 字段名 / 类型（带中文名，可手写）/ **子类型**（选到容器才出现）/ **配置方式** / **单元格格式** / 分组（**中文下拉**）/ 注释；类型下拉含基础类型、容器、以及公共与当前表专用的枚举 / 结构 |
| **容器字段** | 类型下拉直接能选 `list` / `array` / `set` / `map`，选完自动带出**子类型**下拉：`list` 等给一个「元素」，`map` 给「键」+「值」两个；子类型清单与类型下拉同源，改子类型实时重算类型串并保留 `#sep=` / `#size=` |
| 自定义类型 | 字段表「类型」下拉的末项「＋ 新建自定义类型…」可建 bean / enum，选「公共」或「当前表专用」，写入前自动备份。「结构 / 枚举」与「归属」两组单选框**互不干扰**；底部「取消 / 确定」居中放大。**当前表专用**写到 `Defines/` 下以该表命名的 xml（`TbDemo.xml`）并自动登记进 luban.conf，不污染公共定义；新建配置表页里填了表名同样可选「当前表专用」 |
| **多列表头** | 配置方式为「流式 / 多级表头 / 多行」这类**多列**填法时，生成模板会把该字段的 `##var` / `##type` / `##group` **合并成一个单元格**（Luban 里它们本来就属于同一列），并染成**黄色**——相邻两个多列字段深浅交替，避免看成一整块；下面再多一行 `##` 备注，写明每列是第几个元素（`items[3/4]`）。预览里的颜色与真实文件一致 |
| **单元格格式** | 官方「紧凑格式」四选项：`stream（默认）` / `lite` / `json` / `lua`。只对结构 / 容器有意义（基础类型显示 `—`）；选了 lite/json/lua 后整格写一个值，「配置方式」自动禁用。保存时 `#format=xxx` 会写回数据表 `##var` 的**字段名**上（写前备份），模板预览与示例值也按该格式渲染 |
| **配置方式** | 下拉内容**由类型决定，且与类型助手的「常用标签」一一对应**：展开方式（流式 / sep / 列限定 / 多行 / 多态）之外，还有校验标签（引用 / 范围 / 资源路径 / 本地化 / 长度约束）。该类型的每一种方式，右侧「配置方式」页签都给一张可抄的示例表 |
| **类型助手** | 独立对话框，分**四块**：顶部标题 / 左侧类型 / 右上**常用标签** / 右下**配置示例**。常用标签**随所选类型变化**；类型列表含通用的 **bean / 多态bean**（纯讲解，不依赖工程），并列出本工程可用的结构与枚举 |
| 模板生成 | 按每个字段选的「配置方式」生成表头（流式 / sep / 列限定 / 多行），带 `##type / ##group / ##` 行和示例数据 |
| 静态自检 | 不跑 Luban 就先拦住：重复定义、index 不在字段里、多主键配错 mode、容器元素可空、字段名不合规……（**界面入口已隐藏**，保存前的自动校验仍然生效） |
| 生成并校验 | 调 Luban.exe，解析报错，把「哪张表 / 可能什么原因」列出来（**界面入口已隐藏**；发布工程走同一条解析链路） |
| **发布工程** | 工具栏加粗入口（紧跟「打开工程」）。把 gen.bat / gen.sh 的**全部参数摊开成一张可编辑的表**：**基础参数**照官方模板脚本（**执行方式** / 可执行文件 / `--conf` / `-t` / `-c` / `-d` / 两个输出目录），**高级参数**照官方 CLI 全参数（`-s` `-p` `-f` `-i` `-e` `-o` `--variant` `--timeZone` `--customTemplateDir` `-l` `-w` `-v` `--validationFailAsError` 与常用 `-x` 扩展），点「更多」才展开；**每个参数都带备注含义**（悬停看全文）。**执行方式** dll（默认）/ exe 二选一，选 dll 命令自动补 `dotnet`；**可执行文件与配置文件会先去工程目录自动查找**（含下一层子目录），找到就自动填上、找不到留空等用户手填；`-t` / `-c` / `-d` 用**下拉**（`-t` 的选项取自 luban.conf 的 targets；`-c` 默认 cs-simple-json，`-d` 默认 json），文件 / 目录参数**既能手输也能点「选择…」**。实时命令预览 + 一键复制；点「**发布**」就是**直接调系统命令执行脚本**（Windows 上是 `cmd /c gen.bat`，跟在资源管理器里双击它一样）。发布时可选**是否覆盖已有脚本**——覆盖则写回 gen.bat / gen.sh（自动备份）并直接执行它；不覆盖则在**工程根目录**另存一份 `gen_时间戳.bat` 再执行，**成功后弹窗问是否删除**这份临时脚本（失败则保留，方便双击看报错）；报错解析后在状态栏给出「错误 N 条 / 警告 N 条」 |
| **管理自定义类型** | 工具栏深色按钮（只在打开了 Luban 工程时出现）。三区界面：顶部标题 / 左侧「所有 + 公共 + 每张表名」/ 右侧类型列表（类型、**引用次数**、引用位置、删除按钮）。引用次数是**真扫整个工程**：每张表的表头字段（含容器元素）、每个结构的字段、表声明的「行结构类型」；为 **0 标红**＝没人用。公共类型显示「表名.字段名」，表专用类型默认只显示字段名、被**别的表**引用时补表名并标「跨表」。删除有**二次确认**：被引用的会列出全部引用位置，还有子结构继承时直接拒绝；可勾「只看没被引用的」批量清理 |
| 保存成功提示 | 保存 / 删除表后底部浮一条自动消失的轻提示（不打断连续编辑），状态栏同步留一条 |
| **知识点** | **顶部工具栏按钮**，点开**独立的非模态窗口**（能开着继续改表）：搜索框 + 条目列表 + 正文，23 条概念 / 规则 / 常见错误；打开时自动带上当前表字段推导出的关键词（选了 `list` 就预填 sep、容器、流式规则） |
| 四区布局 | 顶部功能区（工具条）/ 左侧工程区（「工程目录」标题 + **打开**按钮 + 目录树）/ 中间文件区（编辑器 · 只读预览 · 新建表）/ 右侧上下文区（配置方式 · 模板预览） |
| 目录浏览 | 打开工程后**左侧就是它的完整目录树**：单击在中间区预览 / 编辑，**双击文件用系统默认程序打开**（Excel 表就是 Excel；双击目录仍是展开 / 收起）；右键菜单也补了「用系统默认程序打开」；左侧标题右侧的「**打开**」按钮一键用资源管理器打开（悬停显示工程路径） |
| 改动标红 + 底部保存 | 表定义与字段的改动先进缓冲区并**标红**，模型/xlsx 不动；点**底部**「保存」才写回（写前备份），「取消修改」整批丢弃。保存条**只在有改动时出现**，保存**只校验当前这张表** |
| 新建表不弹窗 | 工具栏「新建表」把表单**内联在中间区**，填完点「创建」直接进编辑器；不用再开关一个对话框。表单里有「**表声明文件类型**」单选：**Excel Schema**（默认，声明写进 `__tables__.xlsx`）/ **XML Schema**（声明写进 xml 定义文件，没有就自动建 `tables.xml` 并登记进 luban.conf），目标文件就在单选旁写明 |初始字段区与「预览表」的字段表**功能完全一致**（新建类型 / 手写类型 / 配置方式 / 助手 / 增删上下移），选中字段时右侧同步刷新 |
| 记忆上次工程 | 启动时若上次的工程目录还在，直接打开；否则回到只有三个入口按钮的首页 |
| **xml 定义也能用** | Luban 允许把定义写在 `Defines/*.xml`（而不是只认 `__tables__.xlsx`）。现在**所有登记过的表定义文件都会被读**（xlsx 与 xml 混着也行，`<module name>` 当命名空间前缀），因此「声明在 xml 里的表」的数据文件**点开就能编辑**，不再误判成只读。表声明的增删改写回**它原来所在的文件**（xml 用手写文本方式改：保留注释、缩进与顺序，写前备份）；xml 里的 bean / enum 也能写（公共写 `Defines/beans.xml` / `enums.xml`，表专用写 `Defines/<表名>.xml`） |
| 创建 / 初始化工程 | 首页「创建 / 初始化 Luban 工程」（或打开空目录后点橙色条幅的按钮）；一键生成 luban.conf / gen.bat / gen.sh / **Schemas**（xlsx 定义文件）/ Defines（xml 定义文件）/ Data（数据表）；schemaFiles 同步指向 `Schemas/xxx.xlsx`（xlsx、xml 可选） |

## 4. 四条设计红线（改代码前请先读）

1. **绝不整体重建工作簿。** 只改目标单元格，样式、批注、其它行列原样保留。
   实现见 `exceldef.py`，`load_workbook(data_only=False)` + 单元格级写。
2. **写盘前必备份。** 自动落到 `<定义文件目录>/_lubankit_backup/`，保留最近 20 份。
   顺手把工程放进 git，双保险。
3. **不猜分隔符。** sep 一律取自 bean 定义（或你手写的类型串），不因为表里看到中文逗号就替换。
4. **能力不够就拒绝，不硬写。** 例：`__beans__.xlsx` 是嵌套字段列布局且字段数超过列组数时，
   工具直接拒绝写入并建议改用 `read_schema_from_file=true`，而不是替你改表头结构。
   同理：**表列表为空时拒绝保存**（否则会把 `__tables__.xlsx` 抹成只剩表头，全工程瞬间变只读）；
   **一行都没写进去时也拒绝**，不允许再出现"报告已保存、其实什么都没写"。

> **表头解析的一条硬规则**（曾经因此整项目读不出表）：只有**再写一行 `##var`** 才算二级
> （嵌套）表头 —— `__beans__.xlsx` / `__enums__.xlsx` 就是这么表达的。
> 表头下面那行 `##` + 中文列名（`##`、表名、行结构类型…）是**整行的行说明**，
> 不是二级表头。把它当二级表头会让每一列都带上 `sub`，而取值/写值都要求"没有 sub"，
> 结果就是**既读不出来也写不进去，还一律报告成功**。

python tests\smoke.py

保存只校验当前表 / 新建表内联且字段区与编辑器一致 / 手写类型生效 / 容器类型与子类型下拉 /
分组中文下拉 / 单元格格式 / 多列表头合并与黄色深浅 / 列序备注行 / **发布工程参数面板（执行方式 · 自动查找 · 基础 / 高级 · 下拉 · 选择 · 覆盖开关）** /
双击文件用系统默认程序打开 / **管理自定义类型（引用统计 · 为 0 标红 · 公共带表名 · 跨表补表名 · 二次确认删除 · 子类型拦截）** /
删除表声明与数据文件分开 / **表专用类型独立定义文件与归属往返**）** → 对话框（类型助手四区 + 常用标签随类型变 + 通用 bean +
两组单选框各自独立 + 配置方式标题加大与当前选择标绿）,
全绿才算过。**不需要真实的 Luban.exe。**

`e2e.py` 走**真实界面流程**：工具建工程 → 写结构 → 用界面新建带 `list` / `map` 字段的表 →
生成模板 → 保存定义 → **重开工程**，重点断言容器类型串（含 `(Reward#sep=,)` 这类带括号的
元素类型参数）经过落盘往返后仍然完整、子类型下拉能正确回显。跑完自动删除临时工程。

> 写定义文件的测试必须**落盘再读回来**。只断言"保存返回成功"是不够的：
> 曾经的 bug 就是保存静默空操作、却一路返回 True（见 §4 的表头解析硬规则）。
> 另一类只有往返才暴露的 bug：用裸 `split(",")` 解析容器类型串，会把
> `(map#sep=|),string,(Reward#sep=,)` 的元素类型拆成 `(Reward#sep=` + `)` —— 单点测试
> 全过，落盘再读回才露馅。解析容器参数必须**括号感知**地拆。

## 9. build.bat 闪退 / 卡住 / 失败怎么办

脚本用**双阶段 + 双写**设计，保证任何情况下你都能看到过程：

- 外层：调用自身（`--inner`），整体输出重定向进 `build.log` 留档
- 内层：进度用 `echo xxx` 写日志，同时用 `echo xxx > CON` **绕过重定向直接打到屏幕**
- 结果：屏幕实时滚动，`build.log` 同时完整留档，最后回显 + `pause`

> 早期版本把输出全重定向进了文件，导致打包那几分钟屏幕全黑，看起来像卡死——已修。

出错时**第一件事是看 `build.log`**：它按阶段留了完整输出，比屏幕回显更全。

| 现象 | 原因 | 处理 |
|---|---|---|
| 窗口一闪就没了 | 旧版 bat 是 LF 换行 + UTF-8，cmd 解析错乱 | 用新版（已改为 **GBK + CRLF**） |
| 黑屏很久、光标闪但无输出 | 旧版的输出重定向问题 | 新版已修；仍遇到就确认是不是旧文件 |
| 日志停在"没有找到 Python" | 没装 Python 或没勾 Add to PATH | 装 Python 3.9~3.12，**务必勾选 Add to PATH** |
| `.venv` 创建失败 | 用户名/路径含中文或空格 | 脚本已自动回落：直接用系统 Python 打包 |
| `pip install` 失败 | 网络不通 / 需要代理 | 手动执行 `.venv\Scripts\python.exe -m pip install -r requirements.txt` |
| PyInstaller 打包失败 | Python 版本太新（3.13+） | PyInstaller 6.22+ 已支持 3.13；仍失败就换 Python 3.11 |
| 之前能跑，用 VS Code 改完就闪退 | 被存回了 UTF-8 或 LF | 确认右下角是 `GBK` + `CRLF` 再保存 |

**耗时预期**（首次，取决于网速与磁盘）：

| 阶段 | 时长 | 屏幕表现 |
|---|---|---|
| 探测 Python / 建 venv | 几秒 | 有输出 |
| 下载依赖 PySide6 等 | **3~8 分钟** | pip 进度实时滚动 |
| PyInstaller 打包 | **2~5 分钟** | INFO 行实时滚动 |
| 自检 + 打 zip | 10~30 秒 | 有输出 |

第二次运行会复用 `.venv`，全程通常 1~3 分钟。

**不知道是哪一种？** 双击 `环境检测.bat`，它会把 Python 命令、版本、路径、
关键文件是否齐全、磁盘剩余空间、上次日志末尾 20 行全部写进 `环境检测结果.txt` 并显示出来。
报错时把这个文件和 `build.log` 一起发出来即可定位。

> 修改这些 .bat 时注意：**必须保存为 GBK/ANSI 编码 + CRLF 换行**。
> 用 VS Code 另存为 UTF-8 或 LF，会重现"闪一下就没了"的故障。

## 10. 为什么 VS Code 打开 .bat 是乱码（以及怎么配好）

**这不是文件坏了，是必然取舍。**

| 谁在读 | 期望编码 | 说明 |
|---|---|---|
| `cmd.exe` | **GBK（cp936）** | 存成 UTF-8 会解析错乱 → 窗口一闪就没了 |
| `VS Code` | UTF-8（默认） | 打开 GBK 文件就显示乱码 |

实测一条真实内容：`探测` 的 GBK 字节是 `CC BD B2 E2`，按 UTF-8 解码会在 `B2` 处直接报错，
于是显示成替换字符或错字。**两边要求相反，只能二选一，我选了 cmd.exe 能跑。**

### 立刻看（一次性）

在 VS Code 里打开 bat → 右下角状态栏点编码（显示 `UTF-8`）→
选 **Reopen with Encoding** → 搜 `GBK`，选 **Simplified Chinese (GBK)**。

### 一劳永逸（推荐）

仓库里已带 `.vscode/settings.json`，打开这个文件夹会自动生效：

```jsonc
"[bat]":       { "files.encoding": "gbk" },
"[plaintext]": { "files.encoding": "gbk" },   // 使用说明.txt 也是 GBK
"files.eol":   "\r\n"                        // Windows 批处理必须 CRLF
```

效果是：`.py` / `.md` 仍按 UTF-8，`.bat` / `.cmd` 自动按 GBK 打开**并且保存时也是 GBK**，
不会手滑存回 UTF-8 又导致闪退。

### 编辑 bat 后必看一眼

改完保存前，确认状态栏右下角显示的是 **`GBK`** 和 **`CRLF`**。
只要这两个对，双击就一定能跑。

> 如果你更习惯 PowerShell：也可以改写成 `build.ps1`（UTF-8 with BOM 即可正常显示中文），
> 但对方双击 ps1 常被执行策略拦住，需要 `Set-ExecutionPolicy`，
> 对"发给同事直接用"这个场景反而更麻烦，所以这里仍然用 bat。

## 11. 分发的注意事项

- **不能跨平台构建**：PyInstaller 必须在目标系统上跑，Windows 的 exe 只能在 Windows 上打。
- **VC 运行库**：PySide6 wheels 需要 MSVC 运行库，Win10/11 一般自带；
  老机器报缺 DLL 就装 `vc_redist.x64`。
- **杀软误报**：PyInstaller 的 exe 常被误报，加白名单；别开 UPX（更容易被报）。
- **体积主要来自 Qt**：`libicudata` 一个就 30MB 左右，这是 Qt 硬依赖，砍不掉。
- 源码全在本地、不联网、不上传任何数据。
